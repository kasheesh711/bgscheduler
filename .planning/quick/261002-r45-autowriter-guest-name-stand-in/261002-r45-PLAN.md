# Autowriter: a guest named as the student stands in at the normal 50% attendance bar

## Context

The autowriter dashboard showed Peat's class with Emmika (Emmie.Wi) Wibawa (2 Oct, 16:00–17:30 BKK, Wise session
`6a8abf58ee79651b10af02e8`, class `6a40777b3bff24c15ccf630d`) as **Out of scope · `student_count_2_guest`**.
The suspected cause was Peat joining with more than one account. The investigation (one approved prod read plus one Wise GET) shows it was not:

| Participant | Wise account | Attendance | Autowriter treatment |
|---|---|---|---|
| Kasidej (Peat) Jungrakangthong Online | teacher | 5583s | teacher |
| Kasidej Jungrakangthong | guest | 98% | dropped as the tutor (the 29 Sep `tutorSelf` fix works) |
| Emmika (Emmie.Wi) Wibawa | student | 0s | the student |
| **emmieeee** | guest | **65%** | counted as a second student |

Emmie joined through a Zoom guest link as "emmieeee" instead of her Wise account. `guestStandsInForStudent`
(`src/lib/feedback-autowriter/session.ts:323`) needs the guest at `AUTOWRITER_GUEST_STUDENT_MIN_PERCENT` = 80%.
She was at 65%, so no stand-in was made, and `accountAndGuest` returned `student_count_2_guest`. That becomes
`skipped_scope` after the 60-minute settle window.

**Owner decision (2026-10-02):** when the guest's name matches the student's own name, the guest stands in at
the normal `AUTOWRITER_MIN_ATTENDANCE_PERCENT` (50%). A guest with an unrelated name keeps the 80% bar. The tutor's
80% bar does not change.

## Approach

Work in a reused agent worktree (`.claude/worktrees/slot-a` or `slot-b`, per the worktree policy) on a new branch
`fix/autowriter-guest-name-stand-in` from `origin/main`. Do not touch the dirty `codex/outlook-calendar` checkout.
Start through `/gsd-quick`.

### 1. Name match helper (`src/lib/feedback-autowriter/session.ts`)

Add `guestNamedAsStudent(guestName, accountName): boolean`:
- **Student words:** use `parseStudentName(accountName)` from `prompt.ts` for `firstName` and `nickname`
  ("Emmika (Emmie.Wi) Wibawa" gives "Emmika" and "Emmie"). Add the surname, which is the last word after the
  parenthetical is removed.
- **Guest words:** split the guest name on anything that isn't a letter or mark, strip a possessive `'s`, and drop
  `GENERIC_GUEST_WORDS` (export it from `prompt.ts`, which does not import `session.ts`, so there is no cycle).
  Dropping those words means "Mom's iPad" never matches.
- **Comparison:** NFKC, lowercase, then collapse repeated letters (`/(\p{L})\1+/gu` → `$1`), so "emmieeee" and
  "Emmie" both become "emie". Words match only on exact equality after collapsing, never as a prefix or substring.
  Ignore words shorter than 3 letters after collapsing, so "Wi" never counts.
- A nameless guest never matches, so it keeps the 80% bar (current behavior).

### 2. Use it in `guestStandsInForStudent` (`session.ts:323`)

```ts
const guestBar = guestNamedAsStudent(guest.name, account.name)
  ? AUTOWRITER_MIN_ATTENDANCE_PERCENT
  : AUTOWRITER_GUEST_STUDENT_MIN_PERCENT;
if (guestPercent === null || guestPercent < guestBar) return null;
```

Everything else stays as it is: the account must be under 50%, the tutor must be at 80% or more, it applies to
`ONE_TO_ONE` only, and to exactly one account plus one guest. Update the JSDoc on `guestStandsInForStudent` and on
`AUTOWRITER_GUEST_STUDENT_MIN_PERCENT` (`types.ts:24`) to state the name-match exception, citing the
Emmie/Peat case of 2 Oct as the owner rule.

### 3. Tests (`src/lib/feedback-autowriter/__tests__/session.test.ts`, the stand-in `it` at about line 134)

- The existing 79% case uses guest "Krit Kaewmanee", whose name now matches the account
  "Wichai (Krit.Ka) Kaewmanee", so at 79% it would now stand in. Change that case to an unrelated guest name
  (for example "Zoom user") so it still asserts `student_count_2_guest`.
- New cases, using synthetic names only (the repo rule from 25ef9f2b):
  - A name-matched guest with stretched letters at 65% ("aimmm" for account "Somchai (Aim.Ka) Kaewmanee"): stands in, gate `ok`.
  - A name-matched guest at 49%: no stand-in, `student_count_2_guest`.
  - An unrelated guest at 65%: no stand-in.
  - A guest with only generic words ("Mom's iPad") at 65%: no stand-in.
  - A two-letter overlap ("Ka") does not match.
  - A name-matched guest where the tutor was under 80%: no stand-in.
- Unit tests for `guestNamedAsStudent` covering the nickname, the first name, the surname, the possessive
  ("Aim's iPad" matches), and the Thai `mae` word being dropped.
- Check `job.integration.test.ts` and `replay.ts` for fixtures that rely on a guest being 79% or under. Both
