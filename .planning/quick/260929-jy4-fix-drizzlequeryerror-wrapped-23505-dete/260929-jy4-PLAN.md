<objective>
Make the eight single-flight / idempotency guards recognise a Postgres unique violation (SQLSTATE 23505) that arrives wrapped in drizzle-orm's `DrizzleQueryError`, so a real concurrent-insert race takes its skipped / already-created path instead of rethrowing.

Purpose: drizzle-orm 0.45 wraps EVERY driver error in `DrizzleQueryError` (`pg-core/session.js` `queryWithCache`, used by both neon-http and node-postgres). The pg error that carries the SQLSTATE is on `.cause`; `.code` on the thrown error is `undefined` and its message is `Failed query: insert into ...` (no index name). Guards that check only `.code === "23505"` therefore never match a real race: the loser rethrows (HTTP 500 / failed cron audit) instead of returning 202 / skipped. The unit tests passed only because they hand-built raw `{ code: "23505" }` errors. Verified for this plan against a real Postgres through drizzle node-postgres: wrapper `DrizzleQueryError`, `.code` undefined, `.cause` a pg `DatabaseError` with `.code === "23505"` and `.constraint === "oft_sync_single_running_idx"`; the legacy check returned `false`, the fixed check returns `true`.

Output: eight source files with a corrected private `isUniqueViolation`, eight test files (three new) covering raw / wrapped / real-DrizzleQueryError / non-unique cases, committed in two atomic commits (Group A = the four sites the user listed; Group B = four further sites with the identical bug, kept separate so the user can drop it).

function isUniqueViolation(err: unknown): boolean {
  if (typeof err !== "object" || err === null) return false;
  // drizzle-orm wraps driver errors in DrizzleQueryError; the SQLSTATE is on `.cause`.
  const candidate = err as { code?: unknown; cause?: { code?: unknown } };

}
