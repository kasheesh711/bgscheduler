# 261003-12b: nightly Opus 5.5 max audit of autowriter posts (outcome)

  - Failure-mode registry M01–M17, with the auditor rubric generated from it.

- **Results.** 14 AI posts audited, all already owner-approved: 6 accurate, 2 cosmetic, 6 major, 0 critical.
- **Where the errors came from.** All 5 summary-only posts were major (speakers "unclear", so the writer fell back to the Wise summary). On the transcript route, 1 of 9 was major.
- **Failure modes.** M05×5, M09×5, M06×2, M07×1, M08×1, M17×1.
- **Proof of model.** Every audit's usage names `claude-opus-5-5`.
- **Spend.** About $51 Claude API-equivalent, all on the subscription and including about $17 of first-night waste. Soniox $0.89; 14 Wise reads.
- **Flags.** One agent flag per major class (6), so each returns to the owner's review list.

## The unattended run

- **What it runs.** Scheduled task `bgs-autowriter-nightly`, at 01:30 BKK (the app adds jitter). It runs `~/.bgscheduler-nightly/bin/nightly` `run` → `verify` → `correct` → `summary`.
- **Which code.** The reserved slot, pinned to the reviewed commit (`runnerSha`).
- **When it may edit Wise.** `correct --apply` refuses until the slot is exactly `origin/main`. Until PR #158 and #159 are merged and the slot is moved, corrections stay signed proposals for the owner.
- **Permissions.** The app starts the task in the main checkout, so the wrapper needs an allow rule there. The owner sets it.

## Lessons

- The summary-only route is the main error source, and neither the production judge nor careful mode can see past the summary. The lasting fix is to give the writer and judge the Zoom captions (with names). That needs owner-protected files and is the next PR.
- `verify` caches its decision per class and post hash. To re-verify, move `verify/<sid>.json` aside.
- The build and the first night used up the owner's weekly Claude limit. A busy night is about $45 API-equivalent; the caps are $60 a night and $300 a week.
