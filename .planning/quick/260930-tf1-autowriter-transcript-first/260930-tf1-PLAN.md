# Autowriter: transcript first, with the summary as the fallback

Scope copied from the approved plan (`~/.claude/plans/for-online-classes-i-inherited-moonbeam.md`, Change 2).
Real student names from the 29 Sep incidents are "student A" (the class where another student's words were
given to ours) and "student B" (the summary that invented "three remaining homework problems") here, in code,
tests, docs and the PR.

## Hard rules
- Work only in `.claude/worktrees/slot-b` on `feat/autowriter-transcript-first`; Node 22; no `npm ci`, no build.
- No writes to Wise or to the production database, no env changes. The replay reads only: Wise session-detail
  GETs, database SELECTs, Soniox jobs deleted in `finally`, model calls recorded in memory.
- Never run the CLI's write modes (`--sweep`, `--process`, `--mode`, `--resume`, `--tutor-on`, `--retry`).
- Synthetic names in tests and docs (public repo). Commits end with the Claude co-author line.
- Draft PR against `feat/autowriter-accuracy-v4`; never merge, never ready, never auto-merge.

## Why
Both 29 Sep errors came from Wise's AI summary: redaction left another student's name as the only real name, and
the summary itself mis-heard a Thai exchange as "three remaining homework problems". The transcript of the
recording (Soniox, Zoom-aligned speakers) carries neither error. Owner decision (30 Sep): for all five tutors,
wait for the recording and write from the transcript; use the summary only as the fallback.

## Tasks
1. **Switch.** `FEEDBACK_AUTOWRITER_TRANSCRIPT_FIRST` (exact `"true"`, `config.ts`) → `deps.transcriptFirst` in
   `dispatch.ts` and the CLI. Acts only while the second pass is on (`transcriptsEnabled && soniox`).
2. **Handover** (`processLeased`): after every gate — attendance, submission (`skipped_human`), scope, form,
   billing (`planPost`), student/tutor — and before anything uses the summary. The readiness wait does not need
   the summary (`requireSummary: !transcriptFirst`). Reason `transcript_first`; `metadata.handover` +
   `metadata.summaryAtHandover {characters, thaiShare}`. Due now when Wise already has the recording
   (`handOverToTranscript` gains an optional `retryInMs`); otherwise the usual recheck, clamped to the fallback time.
3. **Fallback to the summary**, only for `handover = transcript_first` rows without `summaryFallback`:
   no recording 3 h after the class end, `recording_multiple_parts`, `speakers_unclear`, 3 Soniox failures, the
   transcript pass switched off while waiting → `fallBackToSummary()`: `pending`, `evidence = summary`,
   `metadata.summaryFallback {cause, at}`, due now, new `ProcessResult` `summary_fallback`.
   Stay holds: `recording_too_short`, `transcript_too_short`, a transcript draft failing the judge or validator.
   In fallback: a Thai summary → held `thai_summary_no_transcript`; a held summary draft stays held; no summary →
   retry, `no_summary` alert and expiry as today. No loops (`mayHandOver = secondPass && !fallback`).
   `retryHeldSession` clears `summaryFallback`, `summaryAtHandover`, `handover`.
4. **Store.** `flagNoRecording` skips transcript-first rows; fallback rows are done with their Soniox job
   (review window, then deletion; going live does not restart the window).
5. **Dashboard.** "Waiting for the recording"; "No recording after 3 h — from summary" and the other causes;
   fallback counts by cause; class end → post median / p90 by evidence.
6. **Replay.** No-behaviour-change refactor first: `sonioxJobInput()` and `buildTranscriptEvidence()` shared by
   production and the replay. New `replay.ts` + CLI `--replay [--sessions=a,b] [--per-tutor=4] [--days=7]
   [--keep-transcripts]`, typed so it cannot post (`Pick<WiseFeedbackOps, "getSessionDetailById">`, no database
   handle). Per class: outcome, Soniox minutes / $ / turnaround, speaker method and shares, the v4 transcript draft,
   its judge at `high` and — on the same messages — at `medium` (tokens, latency), a v4 summary draft, and a v4
   `high` judge of the already-posted draft (the original, before any correction) against the transcript. Output to
   gitignored `.feedback-autowriter/replay/<ts>/` (0600) with `summary.md`; transcripts only with `--keep-transcripts`.
7. **Tests** (Testcontainers + unit): handover and gate order; no summary wait; transcript → `verified` end to end;
   each fallback cause; holds that stay holds; no loops; alert suppression; retention of fallback rows; retry
   clearing; replay safety; `buildTranscriptEvidence` / `sonioxJobInput`.
8. **Docs.** Feature page, runbook (switch, fallback, tutor message, rollback), env reference.
