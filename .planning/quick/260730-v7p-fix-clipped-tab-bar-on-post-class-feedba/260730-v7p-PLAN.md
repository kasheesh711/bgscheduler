# Fix the clipped tab bar on /post-class-feedback

## Context

On `/post-class-feedback`, the workspace tab row (Operations · Analytics · Deductions · Payouts ·
Audit · Settings) renders with the label text sliced horizontally — tops and bottoms cut off — and
the active-tab underline invisible. Reported after clicking the Audit tab.

Two compounding causes, both in the single `TabsList` at
[post-class-feedback-workspace.tsx:251](src/components/post-class-feedback/post-class-feedback-workspace.tsx:251):

```
<TabsList variant="line" className="mb-3 h-10 w-full max-w-full justify-start gap-4 overflow-x-auto border-b px-1">
```

**Cause 1 — the author's `h-10` never applies.** The shadcn primitive
([ui/tabs.tsx:26](src/components/ui/tabs.tsx:26)) sets `group-data-horizontal/tabs:h-8`. The
`data-horizontal` variant is defined in `node_modules/shadcn/dist/tailwind.css` as
`&:where([data-orientation="horizontal"])`; `:where()` contributes zero specificity, so the compiled
selector scores the same (0,1,0) as the plain `.h-10` utility. `tailwind-merge` does not treat a
variant class as conflicting with a bare one, so both survive `cn()` and the tie is broken by
stylesheet order — the variant is emitted later and wins. **The list is pinned to 32px**, not 40px.

**Cause 2 — `overflow-x-auto` makes the list a scroll container on both axes.** Per CSS overflow
rules, when one axis is set to a non-`visible` value the other computes from `visible` to `auto`. So
the list clips vertically too. When a horizontal scrollbar is present (classic/always-visible
scrollbars, or a narrow viewport), it consumes ~15px of the fixed 32px height. The triggers are
`h-[calc(100%-1px)]`, a percentage of the list's content box, so they collapse from 24px to ~9px
while the 20px line-height text stays put — the text overflows its own trigger and the list's
`overflow-y` slices it. The same clip hides the active-tab underline, which is drawn at
`after:bottom-[-5px]`, outside the trigger box.

### Measured in a compiled-CSS repro

A standalone page was generated from the project's real `globals.css` (compiled through
`@tailwindcss/postcss`) with the exact `cn()`-merged class strings and base-ui's DOM shape
(`data-orientation="horizontal"` on root and list), then measured in a browser:

| Variant | List height | Trigger height | Text fits? |
|---|---|---|---|
| Current markup, 15px horizontal scrollbar | 32px | **9px** | **no — clipped** |
| Scroll moved to a wrapper + `h-10!` | 40px | 32px | yes |

## Tasks

### Task 1 — move horizontal scrolling off the TabsList

**File:** `src/components/post-class-feedback/post-class-feedback-workspace.tsx`

- Wrap `<TabsList>` in `<div className="mb-3 max-w-full overflow-x-auto pb-1">`. The wrapper's height
  is content-driven, so a horizontal scrollbar adds height below the row instead of stealing it from
  the row.
- Change the list to `h-10! w-max min-w-full justify-start gap-4 border-b px-1`:
  - `h-10!` (Tailwind v4 important modifier) beats the primitive's `group-data-horizontal/tabs:h-8`
    on specificity rather than on source order, so the height is no longer accidental.
  - `w-max min-w-full` lets the row span the full width when it fits and grow past it when it does
    not — which is what makes the wrapper's scrollbar meaningful.
  - `mb-3` moves to the wrapper; `overflow-x-auto` is dropped from the list.
- `pb-1` on the wrapper keeps the `after:bottom-[-5px]` underline inside the wrapper's own clip box.

**Do not modify** `src/components/ui/tabs.tsx` — it is a shared shadcn primitive used by other pages.

**Verify:** `npm run typecheck`, `npm run lint`, `npm test`.
**Done:** tab labels render at full height with the underline visible; the row still scrolls
horizontally on narrow viewports.

## Must-not-break

- All other pages using `Tabs` (primitive untouched).
- Existing post-class-feedback tests (`payouts-tab.test.tsx` and the rest of the unit suite).
