# Onsite class evidence and reviewed feedback

Date: 2026-10-01. Status: implemented architecture for a disabled-by-default MVP; production activation is outside this task. See the [activation and recovery runbook](../../operations/class-capture.md) for rollout gates, costs, acceptance evidence, and unverified limits.

## Intent and authorization

Kevin asked for a mobile-friendly BeGifted Ops workflow that records an onsite class and helps its tutor prepare post-class feedback. Success is a tutor selecting their existing scheduled class/student, visibly recording with consent, adding an optional debrief and worksheets, reviewing an evidence-based draft, and explicitly submitting through the existing Wise feedback form.

Implementation, local synthetic tests, an isolated branch, and a draft PR are authorized. Production migrations, data writes, deployment, merge, parent messages, new credentials/OAuth grants/subscriptions, and recording or transmitting real student material are not. The user requested autonomous implementation with reasonable bounded assumptions; the written design records those assumptions without adding optional approval stops.

## Existing system and approach

The app uses Next.js 16.2, React 19, TypeScript, Drizzle/Neon, Auth.js, and the BeGifted sky/amber/cream design system. Follow `AGENTS.md`, `docs/handbook/conventions.md`, and the installed Next.js guides. Business logic stays in `src/lib/class-capture`; routes validate and authorize before reading request bodies.

`src/lib/feedback-autowriter/` already integrates Soniox Thai/English transcription and OpenRouter with zero-data-retention provider routing. Its submission path deliberately excludes onsite classes and preserves Wise's blank auto-submission/billing state. Post-Class Feedback is a compliance and evidence reader. Neither is a safe new onsite submission endpoint.

Use a separate `/class-capture` workspace and `/api/class-capture` namespace, with explicit copy/open-Wise handoff. Reuse the private direct-upload pattern in `src/lib/progress-tests/workspace/files.ts`, the existing provider interfaces where compatible, and `wiseSessionLink` for the final destination. Do not change the online autowriter's selection, submission, feedback deadlines, billing, or payroll policies.

| Approach | Decision |
| --- | --- |
| Separate capture workspace, private uploads, durable jobs, reviewed Wise handoff | Selected: supports phone recovery and isolates the billing-sensitive submit path. |
| Extend online autowriter and automatically submit onsite feedback | Rejected: contradicts explicit review and existing online-only billing gates. |
| Keep all processing in browser memory | Rejected: a refresh, suspended page, or provider wait can lose work; cannot safely hold provider credentials. |

## Phone workflow

1. **Select class.** Show a scoped list with scheduled time and lesson/student/tutor identity. The selected identity stays visible through capture and review. The server derives IDs from authorized stored records; the tutor supplies or edits the lesson topic. The client cannot move a capture to another student.
2. **Consent and record.** Explain recording, provider processing, expiry, and foreground limits before an explicit consent action. Only then request microphone access on a user gesture. Show a persistent recording indicator, elapsed time, and large Stop button. Permission denial, unsupported MIME/API, and device-busy errors leave the normal feedback route available.
3. **Finish evidence.** Playback the saved clip, offer upload/retry/delete, and optionally record a separate short tutor debrief or add written tutor observations. Label debrief as the tutor's report. Add up to four worksheet photos for the tutor's own review; remove any photo independently.
4. **Transcribe and draft.** Show processing, ready, and failure/uncertainty states. English/Thai/mixed input is supported, without promising transcription accuracy. Generation requires an explicit action; durable claims protect against concurrent work. Keep AI generation unavailable while selected audio is ambiguous or required configuration is missing; the tutor can explicitly remove a failed source and use tutor notes.
5. **Review and hand off.** Show source excerpts beside the four editable sections and the warning that audio cannot establish silent or written work. Preserve unsaved edits during polling. Review acknowledgment enables copying the reviewed text and the existing Wise session link. UI says “Open Wise to submit”; it never displays “Submitted” based on a copy/link click.

Use existing navigation and components, accessible labels/status regions, visible focus, high contrast, and at least 44px touch targets. At a 390px viewport the page fits without horizontal scrolling; recording controls remain reachable above mobile browser chrome. Add no unrelated visual redesign.

## State, authorization, and storage

Migration `0108_class_capture.sql` adds `class_captures` and `class_capture_assets`; it is not applied in production by this task. Captures bind the creator email, tutor canonical key, server-derived Wise class/session/student payload, consent/version, topic/notes/draft, review/revision, draft lease/attempts, creation/expiry, deletion, and cleanup-attempt metadata. Assets bind capture, kind, worksheet permission, server-generated pathname, allowlisted MIME/size, processing state, transcript/error, provider IDs/uncertainty, removal, and cleanup-attempt timestamps. No names appear in storage paths.

Asset states are `pending`, `ready`, `transcribing`, `transcribed`, and `failed`. Capture draft/review/version and deletion/expiry fields describe the remaining lifecycle. Transactional limits, compare-and-set claims, and leases reduce duplicate attempts and protect edited text. Save provider IDs when returned. An unknown provider-create outcome blocks automatic replay and requires operator review; feature-specific orphan cleanup deletes old copies but does not reconstruct a lost successful response. Do not promise exactly-once provider billing.

Each request resolves current auth and exact ownership. Do not import the legacy display-name bridge as a new capture authorization rule. Fresh snapshots authorize creation; current session changes also invalidate later use. Scope prior feedback to the same student, Wise class, and tutor, from completed teacher feedback within 90 days, at most three records; never accept browser-supplied history. Access revocation blocks subsequent processing and upload finalization while preserving cleanup metadata.

Upload tokens bind a currently authorized intent, capture, server pathname, MIME, exact size ceiling, and five-minute validity. The browser explicitly finalizes through `POST /api/class-capture/[id]/assets/[assetId]`; there is no Blob callback endpoint. Finalization rechecks ownership and current class access, then verifies private bytes/container signatures, size, and readable bounded images. Reject SVG/HTML, MIME mismatch, oversized audio/images, and cross-capture attachment. Private content is served only by scoped routes with no-store headers; do not serialize server Blob tokens, provider URLs/keys, or raw upstream errors. Never fetch a client-supplied URL.

## Evidence and provider boundary

Class transcript segments and tutor-debrief segments receive different source prefixes and keep their original language. Draft input includes selected lesson metadata and authorized historical context, clearly separated from current evidence. Treat all transcript/debrief/history text as untrusted data, including any text instructing the model to ignore its rules.

Use a strict output schema with four sections and source references. The model selects verbatim excerpts; the application renders fixed attribution labels rather than accepting generated factual paraphrases. Demonstrated understanding may cite tutor notes/debrief only. Validate every cited source ID and quote against the current capture before exposing generated content. Exact quote membership is a traceability check, not proof of semantic entailment; conservative selection and explicit tutor review remain necessary. Limit combined current transcripts to 90,000 characters, tutor notes to 12,000, historical context to three entries of 2,000 characters each, and rendered draft fields to 8,000 characters total. Oversized current evidence yields a visible error rather than silent truncation. Without reliable student attribution, class audio remains an unattributed excerpt rather than proof of mastery.

Reuse `callOpenRouter` with the existing zero-data-retention route constraints. Submit private audio bytes through the Soniox Files API and refer to its file ID; do not make Blob audio publicly fetchable. Delete both Soniox transcription and file objects. Provider tracking references are not idempotency keys, and processing transcriptions can temporarily refuse deletion. [Soniox file upload](https://soniox.com/docs/api-reference/stt/files/upload_file), [transcription creation and deletion behavior](https://soniox.com/docs/api-reference/stt/transcriptions/create_transcription).

## Recovery and deletion

Persist emitted recording chunks and metadata to actor/session-keyed IndexedDB where available; record elapsed time separately from chunk count. On storage quota/private-mode failure, explain that recovery is unavailable and do not silently claim saved work. Reload can recover emitted chunks until expiry, not audio that the browser never delivered. A browser may delay `dataavailable`, including during Android screen locking; Safari may pause capture. [MDN describes these limitations](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event).

Use the existing Blob SDK's multipart retries, progress callback, and abort signal. Keep completed local bytes until upload finalization is confirmed; network loss offers a deliberate retry after reconnection. Cancellation stops microphone tracks and active uploads, makes server content inaccessible, and queues deletion. Duplicate finalization returns the existing ready result. [Blob documents multipart retries and upload cancellation](https://vercel.com/docs/vercel-blob/using-blob-sdk).

Run expiry and cancellation cleanup through the existing authenticated internal feedback-autowriter cron hook, independently of capture/online-autowriting enablement, controlled by `CLASS_CAPTURE_RETENTION_ENABLED`. Retention runs alongside the autowriter job so its existing execution budget is not shortened. Cleanup has bounded batches, stored Blob paths, and a feature-specific Soniox prefix for orphan deletion. Keep failed deletion identifiers and unresolved tombstones; never call pending deletion complete. Successful cleanup retains tombstones at least one hour beyond original capture expiry to catch late work. Feature activation requires evidence this cleanup runs. A missed job must not restore expired access; physical deletion remains subject to scheduler/provider retries.

The sweep uses a 90-second budget and visits at most 25 eligible captures, ordered by cleanup-attempt age with a 15-minute capture cooldown; asset attempt times rotate partial work. The Soniox orphan scan is bounded to five pages of 100 objects per resource type, twenty deletions, and 45 seconds within that budget. A remaining/cyclic cursor, failed deletion, or exhausted budget reports incomplete cleanup. Only a complete successful scan can clear uncertainty on processing attempts older than 24 hours plus three minutes; it does not recover a transcript or authorize paid replay. Stored-ID deletion is the primary path. A shared provider project whose older orphans lie beyond this scan needs operational remediation or durable pagination before activation; repeated bounded scans do not guarantee traversal. Surface `failed` and `deferred` counts; neither a visited capture nor a retained tombstone proves physical deletion complete.
