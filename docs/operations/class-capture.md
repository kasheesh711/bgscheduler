# Class Capture — activation and recovery runbook

Status: the initial owner pilot rollout was authorized on 2026-10-01 for an October 2 Bangkok trial. The follow-up tutor pilot gate scopes every configured participant, including admins, to their own tutor and today's classes in Bangkok. Source defaults remain disabled. See [PR #133](https://github.com/kasheesh711/bgscheduler/pull/133) for the initial deployed commit and activation evidence; a configured flag alone does not prove a successful rollout.

Production preflight on October 1 confirmed the existing Blob store is private, active, and within quota; the designated owner has an active full-access admin record and a matching signed-in access version. Existing Soniox `stt-async-v5` and OpenRouter `openai/gpt-6.1-sol` via Azure had successful production operations that day, inspected as metadata only. This does not verify the new private-file speech upload or extractive draft end to end. Migration 0108 was applied in an isolated transaction and verified against its SHA-256, with both new tables empty. Initial production flags keep capture and paid processing off while enabling retention for the first checked deployment. No new account, credential, subscription, OAuth grant, or security setting was created.

The [design](../superpowers/specs/2026-10-01-onsite-class-evidence-design.md) and [implementation plan](../../.planning/quick/261001-r5j-mobile-onsite-class-evidence-and-reviewe/PLAN.md) describe the MVP. `/class-capture` prepares a draft; the tutor copies reviewed text and opens the existing Wise session form to submit it. It does not submit feedback, message parents, or change payroll, billing, or the online autowriter's submission rules.

## Access, evidence, and file bounds

Every page, API and navigation capability uses the same tutor pilot gate. The normalized signed-in email must belong to the complete valid `CLASS_CAPTURE_PILOT_EMAILS` list (or the singular compatibility setting when plural is absent). Each actor must have an admin or teacher session and exactly one canonical tutor key from a fresh active exact onsite/online contact lookup. Canonical keys retain their source casing. An admin session additionally requires a fresh enabled admin row, the same nonnegative integer access version, and full or explicit `/class-capture` page access. A teacher session must have no conflicting admin row; its existing `/progress-tests` page grant does not need widening. A revoked/deleted/stale admin never falls back to teacher access. `SUPER_ADMIN_EMAILS` grants no capture bypass. Email input is bounded to 320 characters before normalization and 254 characters after normalization; Unicode case-fold lookalikes are rejected before lowercasing.

New listing, selection and creation are restricted by the server to the scheduled start's current Bangkok day. Supplied past/future/malformed dates and forged session IDs are denied. The day is checked again after the asynchronous selection lookup and immediately before a new insert, including requests that cross Bangkok midnight. The UI shows today's own classes without a date picker and refreshes at midnight and on return to the page.

Captures require both their creating email and the actor's one current tutor key on every read, edit, upload, media read, processing action and deletion. Null/multiple scopes and older admin-created captures for another tutor are denied. Existing owned unexpired capture recovery is separate from new selection: crossing midnight does not clear recording, evidence or edits, and an existing-ID storage retry can return the same capture. The selected class/student rules remain in force. A fresh conflicting reassignment, cancellation, roster change, rescheduling, or known deletion denies use. An already owned ended class may leave the future schedule feed without losing its unexpired capture. A currently authorized pilot can delete their own same-tutor capture when class authorization changes or capture is paused. Removing pilot/contact/admin access also denies interactive deletion; scheduled retention continues independently of these user grants.

Participant agreement, required guardian permission, and permission for named provider processing precede capture. Microphone permission is a separate browser prompt. Worksheet permission is confirmed independently. No recording starts invisibly or without an explicit action.

| Item | MVP bound |
| --- | --- |
| Class audio | WebM, MP4/M4A, Ogg, or WAV; up to 100 MiB total across eight active sections. Browser recording stops at two hours or the byte limit. |
| Tutor debrief | One active separate audio source, up to 10 MiB; the browser recorder stops at three minutes. The byte limit is not a server-side pre-spend duration guarantee for an imported file. |
| Worksheets | No worksheet count limit; JPG/PNG files up to 8 MiB and 24 megapixels each. Tutor review only; no OCR or model photo upload. |
| Replacements | Audio has a lifetime budget of 20 intents and 200 MiB total declared bytes, including removed audio. Worksheet uploads do not consume that budget and have no aggregate file-count or byte cap. |
| Current draft input | Combined transcripts 90,000 characters, tutor notes 12,000 characters. Oversized current evidence fails visibly. |
| Prior context | At most three earlier feedback records for the same student/class/tutor, within 90 days; at most 2,000 characters each enter the model. History cannot support a current-class claim. |
| Generated draft | Four fields, at most 8,000 characters in total; excerpts keep class audio, tutor debrief, and written observations distinct. |

The model selects source IDs and verbatim quotes. Unknown sources, invented quotes, prior-feedback citations, and worksheet citations are rejected. Demonstrated understanding can cite tutor observations/debrief only. Class-audio speakers are unverified. Quote membership does not prove the meaning of a claim; the tutor must review context, negation, attribution, and any proposed homework. Audio alone cannot establish silent or written work or mastery.

## Phone recording and after-class feedback

The recorder requests a screen wake lock and shows whether it was granted. This prevents automatic screen sleep when supported; it cannot continue reliably through a manual lock, app switch, or phone call. For a locked-screen iPhone workflow, record with Voice Memos, save/share the file to Files, and select **Upload saved audio**. M4A imports normalize Apple MIME aliases and use the extension plus a container signature check when Files supplies no type. The same canonical MIME is used for local recovery, upload authorization, Blob storage, and server validation.

Recording emits recovery chunks every second when the browser permits. On interruption, it releases the microphone but waits for the recorder's final event, including delayed Safari events, before completing the local file. Chunks not yet emitted before process termination cannot be recovered.

Today's completed classes remain selectable for retrospective feedback. When the student snapshot still labels a class upcoming, a newer ready, nondeleted, recent post-class observation can establish completion only if class, exact teacher user/canonical key, student roster and scheduled times match. Both snapshots retain the two-hour freshness requirement. A missing teacher membership ID is resolved only through a unique exact Wise user membership in the active identity snapshot. Current conflicting schedule rows still take precedence.

**Write feedback myself** opens editable feedback fields without recording, uploading, or calling an AI provider. Review and save the fields, then copy them into Wise. A capture still expires 24 hours after creation. The class picker remains scoped to today in Bangkok.

Selecting worksheet photos starts a sequential private upload automatically after the existing worksheet permission check. Thumbnails stay visible in a three-column gallery with a bounded scroll area; tap a photo for a full preview, or collapse the gallery. Failed or cancelled uploads retain a local retry path. The typed tutor-observations section is removed; prior saved observations are preserved, and new feedback can use the class transcript, voice debrief, or manual feedback fields.

Worksheet photos have no count cap, including the former 20-intent aggregate upload cap. The per-photo format, size, pixel, permission and retention checks remain in place. Audio budgets are unchanged and count only audio intents.

## Upload, retry, and uncertain work

The server creates a private, non-overwritable intent under `class-capture/<capture UUID>/<asset UUID>`. The authenticated token route authorizes its pathname, type, exact declared size, and five-minute lifetime. The browser uses multipart upload and then explicitly finalizes via `POST /api/class-capture/[id]/assets/[assetId]`. **There is no Blob callback endpoint.** Finalization rechecks current scope, reads private bytes, verifies size/container, and validates images before marking evidence ready. Private media reads use scoped, no-store responses.

Keep the original or recoverable local audio until upload is confirmed. A lost response can be checked against the same intent; retry can resend saved bytes. Cancellation aborts the browser upload and keeps local media available for a deliberate retry. The SDK can retry multipart parts, but cross-reload multipart continuation has not been verified or promised. [Vercel Blob SDK](https://vercel.com/docs/vercel-blob/using-blob-sdk).

Transcription and drafting require explicit actions. Stored claims/provider IDs and draft version checks reduce duplicate work and protect edits. A Soniox POST can succeed even if its response is lost: its `client_reference_id` is a tracking value, **not an idempotency key**. The UI reports an uncertain outcome instead of silently resending. Do not clear that state or create a replacement paid attempt without reviewing known provider IDs and cleanup. The feature-specific `bg-capture:` prefix allows orphan deletion; it does not reconstruct a lost successful transcript. [Soniox API](https://soniox.com/docs/api-reference/stt/transcriptions/create_transcription).

For an uncertain or failed audio source, retain the local original, ask the operator to inspect metadata and provider cleanup, or explicitly remove the source and draft from the remaining transcript or write the feedback manually. Never claim transcription succeeded from a missing/failed response. The worker has no proven exactly-once billing guarantee; account spend controls remain necessary.

## Retention and rollback

Capture access expires 24 hours after creation. Delete/cancel makes evidence inaccessible sooner. Cleanup clears transcripts, draft, topic, and tutor notes and retries removal of private Blob bytes and **both** Soniox job and uploaded file. Successful transcription also attempts prompt provider deletion. Provider IDs remain until deletion is confirmed; processing jobs may temporarily reject deletion. Physical deletion can lag logical expiry because of scheduler delays, outages, or provider conflicts.

Successful cleanup retains database tombstones until at least one hour beyond the capture's original expiry to catch late uploads/in-flight work. Tombstones retain ownership/session/consent metadata during that interval; a closed browser's local storage is separate. Browser recovery expires after 24 hours and is purged on a subsequent app visit; another account cannot recover it through this UI. Closing a browser cannot guarantee timed physical deletion, and OS/process termination can lose chunks never emitted by MediaRecorder. Safari may pause capture and Android lockscreen may delay chunks. Keep the page visible; background/lockscreen recording is not supported as a reliable workflow. [MDN MediaRecorder limitations](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event).

The cleanup sweep uses a 90-second budget alongside the existing autowriter job. It visits up to 25 eligible captures per run, including expired/deleted captures, removed assets, and transcribed assets still holding provider IDs. Capture/asset attempt timestamps rotate older or unvisited work first; a 15-minute capture cooldown avoids repeatedly visiting clean tombstones. It reports deferred work when the batch or time budget prevents a visit. Provider and Blob calls use bounded deadlines; production runtime behavior remains unverified.

The Soniox orphan scan is separately bounded to five pages of 100 objects **per resource type**, 20 deletions, and 45 seconds within that sweep budget. A remaining/cyclic cursor, failed delete, or exhausted budget surfaces cleanup failure. A complete successful scan of resources older than 24 hours can clear uncertainty only for processing attempts older than **24 hours plus three minutes**, allowing the original request time to finish. It establishes cleanup progress, not a recovered transcript or permission to replay the paid request. An incomplete scan retains uncertainty and related tombstones. A busy shared provider project can keep older objects beyond the scan indefinitely; repeated bounded scans do not guarantee traversal. Stored-ID deletion is the primary path. Resolve sustained backlog or implement durable scan progress before increasing volume.

Monitor the existing Data Health cron status and response's `captureRetention.enabled`, `ok`, `failed`, and `deferred`. The persisted `cron_invocations.metadata.response` digest retains the top-level `captureRetentionEnabled`, `captureRetentionOk`, `captureRetentionCleaned`, `captureRetentionFailed`, and `captureRetentionDeferred` scalars. Use these fields from a finished scheduled run after the release: enabled/ok must be true and failed/deferred zero. The overall audit outcome alone is insufficient, because an unrelated skipped autowriter result can label the combined invocation skipped. Unknown counts are null, never evidence of zero work. Failed or deferred retention makes the combined route return 503. Its `cleaned` value counts successful capture visits rather than proving every tombstone or provider object is gone. Compare invocation cadence with metadata-only backlog counts: expired/deleted captures, oldest expiry, removed assets, transcribed assets still holding provider IDs, uncertain processing, and cleanup-attempt age. Investigate increasing age, repeat failures, missing credentials, deletion conflicts, or a capped orphan scan. Do not log transcripts, photos, audio, tokens, raw provider bodies, or student names for this purpose. There is no dedicated retention dashboard or alert channel added by this MVP.

To roll back availability, set `ENABLE_CLASS_CAPTURE` and `CLASS_CAPTURE_PROCESSING_APPROVED` off through the approved release process. **Keep `CLASS_CAPTURE_RETENTION_ENABLED=true`, the cleanup scheduler, private-store access, and Soniox deletion access available** until all outstanding copies/backlogs are verified removed. Do not roll back to code without this cleanup hook while retained evidence remains, or drop the new tables while they hold cleanup identifiers. Existing Wise feedback continues separately.

## Operating cost

Prices were checked against primary sources on 2026-10-01; verify current account pricing before activation. This is a planning estimate, not a billing cap.

| Service | Cost model |
| --- | --- |
| Soniox asynchronous transcription | Approximately **$0.10 per audio hour**, token-based billing. A 60-minute class plus a three-minute debrief is approximately **$0.105**, before retries/replacements or other services. [Soniox pricing](https://soniox.com/pricing). |
| OpenRouter | Actual input/output tokens × the configured writer model's current prices, plus any failed or repeated billable calls. The configured writer is `openai/gpt-6.1-sol` with low reasoning and zero-data-retention routing. The public model listing on October 1 showed $2/million input tokens and $10/million output tokens; existing successful production drafts inspected that day cost about $0.027–$0.042 each. These are observations from the existing workflow, not a measured cost for this new extractive draft or an account spending cap. [Model pricing](https://openrouter.ai/openai/gpt-6.1-sol). Prior context, repeated drafts, and long transcripts change the total. |
| Vercel Blob | Stored GB-month × regional/account storage rate, plus simple/advanced operations and transfer. Multipart adds start/part/complete operations; private delivery can add function/CDN transfer. Confirm the actual store region and account plan. [Blob usage and pricing](https://vercel.com/docs/vercel-blob/usage-and-pricing). |
| App/database | Request execution, private-media validation/streaming, metadata/transcript storage, and scheduled cleanup under the existing hosting/database plans. No new subscription was created. |

Daily capture/file/byte limits and bounded attempts reduce accidental load but are not a monetary budget or a pre-transcription duration validator. Longer compressed uploads, operator replacement attempts, outages, and provider billing behavior can increase costs. The processing approval flag is a rollout gate, not a per-request spend authorization service.

### Completed sessions after snapshot rotation

When both active schedules omit a completed class, Class Capture can use its latest retained Wise student-snapshot row within the existing two-hour freshness window. It requires an independently fresh, exact post-class completion record and matching tutor, single-student roster, class, times and onsite evidence. Any active or newer retained row takes priority, including conflicting or cancelled records. Snapshot IDs are bounded before scanning session rows. Today-only access remains in force.
